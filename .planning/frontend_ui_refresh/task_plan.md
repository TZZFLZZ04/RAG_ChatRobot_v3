## 关键问题
1. 哪些页面与高频任务最影响当前体验？
2. 如何在不迁移框架、不改 API 的情况下统一视觉语言？
3. 哪些 DOM id/class 被现有 JavaScript 依赖，必须保留？
4. 当前环境能否完成真实浏览器视觉验证？

## 已做决策
| 决策 | 理由 |
|------|------|
| 默认覆盖三个现有 HTML 页面 | 用户要求优化“目前项目的前端页面” |
| 保留原生 HTML/CSS/JS 技术栈 | 避免无必要的框架迁移与回归 |
| 保持 API、DOM 行为和业务流程兼容 | UI 改造不应改变后端契约 |
| 风格假设为现代企业级 AI 工作台 | 与 RAG 产品定位和高密度工作流相符 |
| 采用 Supabase-inspired 白色技术型视觉系统 | 比 Linear 深色和 Notion 内容型风格更契合当前任务 |
| 仅修改 3 个 HTML、共享 CSS、2 个必要 JS 与页面测试 | 保持外科式范围，不触碰 API 和业务逻辑 |

## 验收标准
- 375px 宽度无横向滚动，登录/评估登录入口不再被整屏空统计阻挡。
- 768px、1024px、1440px 布局层级清楚，工作区不依赖 1000px 固定高度。
- 所有现有 API、路由、表单 id 与动态组件 class 保持兼容。
- 表单具有关联 label，状态区域具备 aria-live，键盘焦点清楚并尊重 reduced-motion。
- `python -m pytest tests/test_web_page.py -q` 通过；前端 80 个 JS DOM id 均可在 HTML 中解析。

## 遇到的错误
| 错误 | 尝试次数 | 解决方案 |
|------|---------|---------|
| 根目录旧规划属于此前 RAG 重构任务 | 1 | 使用 `.planning/frontend_ui_refresh/` 独立保存本次计划 |
| `session-catchup.py` 调用退出码为 1 | 1 | 已人工读取旧规划并隔离新任务，不重复失败调用 |
| `grill-me` 要求 `/grilling`，当前无对应命令 | 1 | 以关键问题、假设审计和验收标准执行等价严格审视 |
| 首次统计文件命令出现 PowerShell 空管道语法错误 | 1 | 将 `foreach` 结果先赋给 `$rows` 再输出，已解决 |
| Awesome DESIGN.md 检索把 PowerShell 参数传给 `rg` | 1 | 后续改为纯 `rg` 参数并分别读取候选文件 |
| 初次隐藏启动 Uvicorn 后进程退出且 8765 无响应 | 1 | 下一步以前台诊断方式捕获实际启动错误 |
| 项目 `venv` 指向已失效的 Python 3.10 路径 | 1 | 改用可用的 Anaconda Python（已安装 FastAPI/Uvicorn）做只读页面审计 |
| 系统 Python 的 Uvicorn 进程存活但长时间未监听端口 | 1 | 停止本次创建的进程，单独诊断 `app.main` 导入耗时/阻塞 |
| 浏览器响应式检查未保留 viewport capability 变量 | 1 | 在下一次调用中重新获取 capability，不重建浏览器会话 |
| 首次跨七文件 HTML/JS 补丁因上下文顺序不匹配而拒绝 | 1 | 已确认无部分写入；改为逐文件、小块补丁 |
| 视觉验证静态服务命令再次触发 PowerShell 空管道解析 | 1 | 使用 `$result` 中间变量，不再直接对 `if` 输出接管道 |
| 浏览器首次视觉验证命中旧 HTML/CSS 缓存 | 1 | 为静态资源增加版本查询参数，并使用带查询参数的页面 URL 复验 |
| 生产化重构首次页面测试缺少旧品牌断言文本 | 1 | 在产品品牌栏保留 `ChatRobot_v3` 与 `RAG Evaluation` 文本，不改变新布局 |
| 内置浏览器首次连接失败：无法写入 kernel assets | 2 | 最小 Node 会话同样失败，确认是浏览器运行环境限制；不切换未授权浏览器，改用静态/服务测试并明确记录 |
| 首次 PowerShell 对比度计算因数组除法优先级失败 | 1 | 改为逐通道显式转换为 double 后计算，不重复原表达式 |
