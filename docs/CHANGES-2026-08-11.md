# Frontend Changes — 2026-08-11

## Summary

Fixed two major UX issues:

1. **Navigation now switches views** instead of scrolling to regions that were already visible
2. **API error messages now show actual validation failures** instead of generic "请求失败"

Plus CSS consistency fixes and responsive improvements.

---

## 1. Navigation View Switching

### Problem

The sidebar had **five nav items** but only **two destinations**:

- 概览 / 知识库 / 文档任务 / AI 对话 were all `href="#anchor"` links on the same page
- 知识库 and AI 对话 sat side-by-side in a 2-column grid, both already visible on wide screens
- 文档任务 was nested *inside* 知识库, so two nav items pointed to the same region
- Active state was hardcoded to 概览 and never updated
- Result: clicking nav items scrolled a few pixels or not at all — felt broken

### Solution

**True view switching** — each nav item now shows a distinct full-width panel.

**Before:**
```
┌────────────┬──────────┬──────────┐
│  Nav (5)   │ 知识库   │ AI 对话  │  ← 2 columns, both visible
│            │  ├ 文档  │          │  ← 文档 nested inside 知识库
└────────────┴──────────┴──────────┘
```

**After:**
```
┌────────────┬──────────────────────┐
│  Nav (4)   │  [Active View]       │  ← One view at a time
│            │                      │
│ • 概览     │  • 概览 → Entry cards │
│ • 知识库   │  • 知识库 → Config   │
│ • 文档任务 │  • 文档任务 → List   │
│ • AI 对话  │  • AI 对话 → Chat    │
└────────────┴──────────────────────┘
```

### Changes

**Navigation:**
- Changed from `<a href="#...">` to `<button data-view="..." aria-pressed>`
- Active state now updates when clicking
- URL hash syncs with active view (`#knowledge`, `#documents`, `#chat`)
- Browser back/forward navigate between views
- Added badge on 文档任务 showing pending document count
- Added refresh button in documents view

**新增：概览视图 (Overview)**
- Entry cards route into the three work views
- Shows at-a-glance summary: "X 个知识库, Y 份文档, Z 条对话"
- RAG 评估 card links to `/evaluations` page

**布局调整:**
- Split old 2-column `workspace-grid` into `.workspace-views` container
- Four sibling `.workspace-view` panels (overview, knowledge, documents, chat)
- Extracted 文档任务 from inside 知识库 so each is independent
- Only one view visible at a time via `.is-active` class

**Live feedback:**
- Badge on 文档任务 nav shows pending count (hidden when zero)
- Context line under 文档任务 heading: `"知识库名 · N 份文档"`
- Description under "知识工作台" updates per view

**Files:**
- `app/frontend/index.html` — Restructured layout, added overview, view switching
- `app/frontend/evaluations.html` — Nav now links back to workspace views
- `app/frontend/static/app.css` — View switching, nav buttons, entry cards
- `app/frontend/static/app.js` — `setActiveView()`, hash routing, live badges

**Test coverage:**
- Added `test_workspace_nav_switches_views_instead_of_scrolling()` to prevent regression

## 2. API Error Message Extraction

### Problem

FastAPI returns validation errors as:
```json
{"detail": [{"msg": "邮箱格式不正确", "type": "value_error", ...}]}
```

But the frontend only read `payload.message`, so users saw a generic "请求失败" instead of the actual field error.

### Solution

Added `extractErrorMessage(payload)` helper that handles:

1. **Backend errors:** `{"code": "...", "message": "..."}`
2. **FastAPI validation:** `{"detail": [{"msg": "...", ...}]}`
3. **Plain text responses**

Now validation errors display the actual problem to users.

### Changes

**Files:**
- `app/frontend/static/app.js` — Added `extractErrorMessage()`, updated 5 fetch error handlers
- `app/frontend/static/register.js` — Added helper, updated 1 handler
- `app/frontend/static/evaluations.js` — Added helper, updated 1 handler

**Usage:**
```js
// Before
setSessionNotice(data.message || "请求失败", "error")

// After
setSessionNotice(extractErrorMessage(data), "error")
```

## 3. CSS Consistency Fixes

### Topbar Height Tokens

**Problem:** Hardcoded `70px` repeated throughout, so changing topbar height required editing 8+ places.

**Solution:** Use `var(--topbar-h)` everywhere.

### Scroll Offset

**Problem:** Section anchors landed underneath the sticky topbar.

**Solution:**
```css
.workspace-view {
  scroll-margin-top: calc(var(--topbar-h) + var(--sticky-nav-h) + 12px);
}
```

### Missing CSS Classes

Added classes that were referenced but undefined:
- `.notice-error`, `.notice-warning` — Session notice variants
- `.toast-error` — Error toast styling
- `.user-message.error` — Chat error message styling
- `.placeholder-text` — Muted text for empty states

### Responsive Improvements

**900px and 760px breakpoints:**
- Now update `--sticky-nav-h` and use variables consistently
- Documents grid stacks to 1 column at 1320px
- Entry grid adapts: 3 cards → 2 cards → 1 card

---

## 4. Session Notice Tones

**Problem:** `setSessionNotice()` accepted a `tone` parameter but didn't apply it.

**Solution:** Now adds the correct class:
```js
setSessionNotice(msg, "error")   // → .notice-error
setSessionNotice(msg, "warning") // → .notice-warning
setSessionNotice(msg, "success") // → .notice-success (default)
```

## Design Notes

**View switching** follows the single-surface pattern — one panel at a time, full width, no distractions.

**Entry cards** use the existing design system:
- Surface ladder: `var(--surface)` base, subtle hover
- Accent soft bg on icon wells
- `var(--radius-lg)` on cards, matching panel geometry
- Fluid typography: `var(--font-display)` for titles

**Nav badges** are 18px pills with `var(--accent)` background, positioned absolute top-right of the nav item.

**Responsive breakpoints** chosen by content, not device:
- **1320px** — Documents grid too cramped at 0.9fr/1.6fr, stack to 1 column
- **900px** — Sticky nav height shrinks, entry cards drop to 2 per row
- **760px** — Entry cards single column, nav items stack

All changes are **backward-compatible** — no API or database schema changes.
